DeepGU

VLM 기반 실시간 CCTV 이상행동 분석 플랫폼

github.com/calmkeep22/2026-1-CECD2-1-Deepgu-06

형태
팀 프로젝트, 캡스톤 디자인
역할
백엔드, 인프라

OBS 영상 송출부터 실시간 알림까지 스트리밍과 백엔드 인프라를 설계하고 구축했다. VLM 이상행동 분석은 AI 팀원이 맡았고, 나는 영상과 이벤트가 지연 없이 흐르는 구조를 담당했다.

처리 흐름

CCTV 영상OBS 송출
→
MediaMTX, FastAPI영상 허브와 이벤트 서버
→
WebRTC 송출영상 지연 약 125ms
SSE 알림50ms 이내 전달
→
관제 화면영상과 알림 실시간 수신

문제와 해결

수 초씩 늦는 영상

HLS 기반 스트리밍은 수 초 이상 지연돼 이상행동에 바로 대응하기 어려웠다. MediaMTX를 스트리밍 허브로 두고 WebRTC 저지연 송출로 바꿔 영상 지연을 약 125ms로 낮췄다.

실시간 이상행동 알림

분석 결과로 나온 이상행동 이벤트를 관제 화면에 바로 보여 줘야 했다. asyncio.Queue 기반 SSE broadcaster를 만들어 연결된 클라이언트에 이벤트를 실시간으로 전달했고, 알림 지연을 50ms 이내로 유지했다.

~125ms

영상 지연, 기존 HLS는 수 초

≤ 50ms

이벤트 알림 지연, SSE

기술Python, FastAPI, MediaMTX, WebRTC, SSE, asyncio

문제와 해결

분석을 기다리던 기록 API

약 3초가 걸리는 LLM 감정 분석이 기록 API를 막고 있었다. 기록 저장과 분석을 분리하고 분석 요청은 RabbitMQ로 넘겨, 메모를 저장하는 즉시 응답하도록 바꿨다.

서로 얽힌 AI 작업

감정 분석, 주간 인사이트, 장소 추천을 각각 별도 큐로 나눴다. 메시지 영속화, TTL, 수동 ACK를 적용하고, 추천 결과는 Redis에 5분간 캐시해 correlation ID로 추적했다.

RAG Code Reviewer

코드베이스와 공식문서를 함께 검색하는 근거 기반 코드 리뷰 시스템

github.com/calmkeep22/langchain

형태
개인 프로젝트
역할
RAG 설계, 백엔드, 검색 품질 평가

프로젝트 코드와 프레임워크 공식문서를 함께 검색해 리뷰하고, 답변마다 코드 위치와 문서 출처를 붙여 결과를 직접 검증할 수 있게 했다.

처리 흐름

리뷰 질문
→
Dense 검색의미 검색
BM25 검색SQLite FTS5
→
RRF 병합파일당 후보 제한
→
근거 기반 리뷰코드 위치와 문서 출처

문제와 해결

의미 검색이 놓치는 코드 식별자

Dense 검색만으로는 함수명이나 클래스명처럼 정확한 문자열이 중요한 질문을 놓쳤다. 코드를 AST 기반 함수 단위로 나누고 Dense와 BM25 검색 결과를 RRF로 합쳤으며, 파일당 후보 수를 제한해 한 파일이 결과를 독점하지 않게 했다.

품질을 떨어뜨린 reranker

FlashRank reranker를 붙이자 한국어 질문 35개 평가셋에서 MRR이 0.82에서 0.29~0.41로 떨어졌다. 측정 결과를 근거로 reranker를 기본 경로에서 빼고 하이브리드 검색을 최종 구조로 택했다.
