DeepGU

VLM 기반 실시간 CCTV 이상행동 분석 플랫폼

github.com/calmkeep22/2026-1-CECD2-1-Deepgu-06

형태
팀 프로젝트, 캡스톤 디자인
역할
백엔드, 미디어 서버, 실시간 알림

CCTV 영상을 실시간으로 받아 AI가 이상행동을 판정하고 관제 화면에 알리는 플랫폼이다. 백엔드, 미디어 서버, 실시간 알림을 맡았고, 이상행동을 판정하는 AI 파이프라인은 AI 팀원이 담당했다.

시스템 구조 실선: 본인 담당, 점선: 팀원 담당

문제와 해결

수 초씩 늦는 HLS 영상

HLS는 세그먼트 단위로 재생돼 수 초 이상 늦게 보였다. MediaMTX가 RTMP 입력을 받고, 관제 화면이 WHEP으로 WebRTC 스트림을 바로 재생하도록 바꿨다. WebRTC 주소가 없는 환경에서는 기존 HLS 플레이어로 재생한다.

분석 결과를 관제 화면에 바로 알리기

AI 워커가 이상행동 이벤트를 백엔드 내부 API로 보내면, 백엔드가 영상과 썸네일을 S3에, 이벤트를 MySQL에 저장한다. 그 뒤 카메라별 asyncio.Queue 구독자에게 SSE로 이벤트를 전달해, 관제 화면이 새로고침 없이 알림을 받도록 했다.

문제와 해결

분석을 기다리던 기록 API

기록 API가 LLM 감정 분석이 끝날 때까지 응답을 기다리고 있었다. 기록 저장과 분석을 분리하고 분석 요청은 RabbitMQ로 넘겨, 메모를 저장하는 즉시 응답하도록 바꿨다.

서로 얽힌 AI 작업

감정 분석, 주간 인사이트, 장소 추천을 각각 별도 큐로 나눴다. 메시지 영속화, TTL, 수동 ACK를 적용하고, 추천 결과는 Redis에 5분간 캐시해 correlation ID로 추적했다.

구현 코드: github.com/2025-OSS-Project/GeoMemo-Backend/blob/dev/core/mq.py

RAG Code Reviewer

코드베이스와 공식문서를 함께 검색하는 근거 기반 코드 리뷰 시스템

github.com/calmkeep22/langchain

형태
개인 프로젝트
역할
RAG 설계, 백엔드, 검색 품질 평가

프로젝트 코드와 프레임워크 공식문서를 함께 검색해 리뷰하고, 답변마다 코드 위치와 문서 출처를 붙인다. 검색 구조를 바꿀 때마다 같은 평가셋으로 다시 재고, 결과를 저장소의 평가 기록에 남겼다.

처리 흐름

리뷰 질문
→
Dense 검색의미 검색
BM25 검색SQLite FTS5
→
RRF 병합파일당 후보 2개 제한
→
근거 기반 리뷰코드 위치와 문서 출처

문제와 해결

공정하지 않았던 첫 비교

AST 기반 함수 단위 청킹을 적용하고 처음 비교했을 때는 MRR이 0.886에서 0.833으로 떨어진 것처럼 보였다. 기준값은 코드베이스가 훨씬 작을 때 잰 수치였고, search_k=5에서는 한 파일의 조각들이 후보를 나눠 차지했다. 같은 코드베이스와 search_k=20으로 다시 재니 AST 청킹이 모든 지표에서 같거나 더 좋았다.

식별자 질문과 reranker

Dense 검색이 놓친 에러 코드 질문을 잡으려고 BM25를 더해 RRF로 합쳤다. 해당 질문을 1위로 찾았고 Recall@5는 0.971을 유지했지만, MRR은 0.856에서 0.823으로 내려갔다. 이를 회복하려고 붙인 FlashRank reranker는 MRR을 0.29~0.41로 떨어뜨려 기본 경로에서 뺐다.

평가 기록: github.com/calmkeep22/langchain/blob/master/eval/results.md
